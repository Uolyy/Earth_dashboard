# Орбитальный пост наблюдения

Дашборд для наблюдения за околоземным пространством в реальном времени:
положение и движение Международной космической станции, её экипаж,
расписание запусков, астероиды, сближающиеся с Землёй, состояние
космической погоды и каталог спутников на орбитах.

В центре интерфейса — трёхмерная сцена Земли с нанесённой траекторией
станции, областью её обзора с поверхности и полярными сияниями.

## Ключевое свойство: проект не требует ни ключей, ни регистрации

Все данные берутся из общедоступных источников, работающих без ключа
доступа и без ограничения частоты запросов. Ни один сайт, где
потребовалось бы завести учётную запись, в проекте не используется.

Изначально в проекте предполагалось использовать сервис NASA по
изображениям Земли, но он требует регистрации и ограничивает десятью
запросами в час. Вместо него используются открытые источники,
перечисленные ниже.

## Быстрый запуск

Требуется Python версии 3.10 или новее. Другие программы не нужны:
все библиотеки устанавливаются автоматически, а библиотеки
для отрисовки уже лежат в проекте.

```bash
# Создание виртуального окружения и установка зависимостей
python -m venv .venv

# Активация окружения (Windows, PowerShell)
.venv\Scripts\Activate.ps1

# Установка зависимостей
pip install -r requirements.txt

# Запуск
python run.py
```

Вместо ручных шагов можно запустить `start.bat` (Windows) или
`start.sh` (macOS, Linux): они сами создадут окружение, починят его,
если оно повреждено, и откроют браузер.

После запуска приложение доступно по адресу <http://127.0.0.1:8000>.

Адрес и порт можно изменить, создав файл `.env` на основе
приведённого в проекте `.env.example`. Файл `.env` необязателен:
приложение работает и без него.

## Зачем нужен собственный сервер

Большая часть источников разрешает обращения напрямую из браузера,
однако часть из них этого не позволяет:

* источник списка экипажа работает только по незащищённому протоколу
  и не объявляет разрешение на кросс-доменные запросы;
* источник сведений об астероидах не объявляет такое разрешение,
  хотя сам работает без ключа.

Собственный сервер решает эту задачу и заодно выполняет четыре
дополнительные функции:

1. **Приводит ответы к единому виду.** Единицы измерения, названия
   полей и форматы дат нормализуются на сервере, поэтому изменение
   во внешнем источнике не приводит к ошибкам в интерфейсе.
2. **Кэширует ответы.** Частота обращений к источникам ограничена,
   а при перезапуске приложения данные не запрашиваются заново.
3. **Рассчитывает орбиту.** Положение станции между обращениями
   к источнику вычисляется на сервере по элементам орбиты,
   благодаря чему движение остаётся плавным.
4. **Следит за состоянием источников.** Маршрут `/api/status`
   показывает, какие данные удалось получить, а какие нет.

## Откуда берётся положение станции

Это самый тонкий момент проекта, поэтому стоит описать отдельно.

Положение МКС известно из двух независимых источников, и они
**не совпадают**:

* `api.wheretheiss.at` сообщает текущие координаты станции, но
  обновляет их примерно раз в секунду;
* элементы орбиты (TLE) — это текстовый набор параметров движения,
  который позволяет вычислить положение станции для любого момента
  времени. Он обновляется примерно раз в сутки.

Поэтому в проекте источники разделены по роли:

* **положение на шаре считает расчёт по элементам орбиты.** Он строит
  и траекторию, и положение станции из одних и тех же данных, поэтому
  станция всегда лежит на нарисованной линии, а движение остаётся
  плавным;
* **панель показывает телеметрию источника.** Так видны показания
  прибора в текущий момент.

Важно, что оба источника не применяются к сцене одновременно: если
передавать координаты станции и от расчёта, и от телеметрии, станция
будет прыгать между двумя точками. Если расчёт по элементам орбиты
становится недоступен, положение станции автоматически переходит на
телеметрию источника.

Расхождение источников — нормальная ситуация. Элементы орбиты
опубликованы в заранее известный момент, поэтому на границах суток
ошибка может достигать нескольких сотен километров.

## Устойчивость к сбоям

Каждая панель работает независимо. Если один источник недоступен,
соответствующая панель показывает сообщение об ошибке, а остальные
продолжают работать. Если источник временно не отвечает, но ранее
получал данные, показывается последний успешный снимок.

Кэш хранится в каталоге `.cache` рядом с проектом и переживает
перезапуск приложения.

## Состав проекта

```
run.py                     Точка входа: python run.py
start.bat, start.sh        Запуск в один клик: создают окружение,
                           чинят его, если оно повреждено, ставят
                           зависимости и открывают браузер
requirements.txt           Зависимости
.env.example               Пример файла настроек
README.md                  Этот файл
install.md                 Установка и запуск для нового компьютера
manual.md                  Подробное описание работы проекта
issues.md                  История исправленных проблем и разбор причин

backend/
    main.py                 Веб-приложение и все маршруты
    settings.py             Настройки: адреса, интервалы, константы
    cache.py                Кэш ответов источников на диске
    http_client.py          Общий HTTP-клиент с повторами
    providers/
        orbit.py            Расчёт орбиты по элементам TLE
        iss.py              Телеметрия станции и экипаж
        launches.py         Расписание запусков
        asteroids.py        Околоземные астероиды
        space_weather.py    Космическая погода и солнечный цикл
        satellites.py       Каталог спутников и элементы орбиты

frontend/
    index.html              Разметка интерфейса
    css/style.css           Оформление
    js/
        main.js             Связывает сцену, панели и графики
        scene.js            Трёхмерная сцена средствами three.js
        panels.js           Панели: телеметрия, экипаж, запуски, астероиды
        charts.js           Графики средствами Chart.js
        api.js              Обращения к серверу
        utils.js            Форматирование значений и времени
    vendor/                 Локальные копии библиотек
    assets/                 Текстуры Земли и значок

.cache/                     Кэш ответов источников, создаётся при запуске
```

## Дополнительные сведения

Подробное описание того, как устроен каждый источник данных, как
считается положение станции, как построена трёхмерная сцена и как
работает модель Земли, приведено в файле `manual.md`.

Файл `issues.md` содержит историю исправленных дефектов с разбором
причин. Указанные там проблемы устранены, но описания сохранены:
по ним видно, почему решение выглядит именно так, и что делать, если
дефект появится снова.
